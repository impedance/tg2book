# План доработок: Повышение стабильности (Stability & Reliability Fixes)

Этот план фокусируется на устранении архитектурных недочетов, утечек ресурсов и потенциальных блокировок (deadlocks) в асинхронном event-loop.

## 1. Устранение утечки потоков (Thread Exhaustion)
**Проблема:** HTTP-запросы в `dropbox_module.py` выполняются без таймаутов. Так как они запускаются в пуле потоков через `asyncio.to_thread()`, зависание серверов Dropbox приведет к исчерпанию пула потоков `asyncio`, и бот перестанет отвечать всем пользователям.
**Решение:**
- В `dropbox_module.py` добавить глобальные константы таймаутов (например, `CONNECT_TIMEOUT = 5`, `READ_TIMEOUT = 30`).
- Обновить вызовы `requests.post()` в функциях `refresh_access_token` и `upload_to_dropbox`, добавив параметр `timeout=(CONNECT_TIMEOUT, READ_TIMEOUT)`.
- Добавить обработку исключений `requests.exceptions.Timeout` с понятным логированием.

## 2. Безопасная работа с файловой системой (File Handle Collision)
**Проблема:** В `bot.py` временный файл создается с помощью `NamedTemporaryFile(delete=False)`, и его контекст (`with`) остается открытым во время вызова `create_epub`. Внутри `create_epub` модуль `zipfile` пытается открыть этот же файл на запись. Это классический случай конкурентного доступа, который уязвим к блокировкам файлов (особенно на Windows, но и в Docker/Linux это bad practice).
**Решение:**
- Рефакторинг логики создания временных файлов в `bot.py` (функции `handle_message` и `_process_uploaded_epub`).
- Вместо удержания открытого дескриптора внутри блока `with`, использовать `tempfile.NamedTemporaryFile` просто для получения уникального пути, сразу закрывать его, а затем передавать путь в `create_epub` и `upload_to_dropbox`.
- Обеспечить надежное удаление сгенерированного файла в блоке `finally:` для гарантированной очистки памяти.

## 3. Разделение зависимостей (Dependencies Isolation)
**Проблема:** Тестовые фреймворки (`pytest`, `pytest-asyncio`, `pytest-cov`) находятся в основном файле `requirements.txt`. При сборке Docker-образа для production-окружения в него попадут ненужные пакеты, увеличивая размер образа и потенциальную площадь атаки.
**Решение:**
- Удалить `pytest`, `pytest-asyncio` и `pytest-cov` из `requirements.txt`.
- Перенести их в существующий файл `requirements-test.txt`.
- Убедиться, что `requirements-test.txt` включает в себя основной `requirements.txt` (через флаг `-r requirements.txt`).

## 4. Обновление и адаптация тестов
**Проблема:** После внедрения таймаутов, логика работы с Dropbox может выбрасывать новые типы исключений (`Timeout`), которые сейчас не покрыты тестами. Также изменится логика создания файлов.
**Решение:**
- В `test_bot.py` обновить моки `requests.post`, чтобы проверить, что параметр `timeout` корректно передается.
- Добавить тесты на симуляцию таймаута соединения и таймаута чтения, чтобы убедиться, что бот корректно обрабатывает такие ситуации и не падает.
