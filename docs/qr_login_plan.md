# План реализации авторизации Юзербота по QR-коду (Pyrogram)

В этом документе описан подробный план по замене неработающей авторизации по номеру телефона (SMS/Код) на механизм входа по QR-коду для Pyrogram. Этот документ предназначен для постановки задач Junior-разработчикам.

## 1. Решаемая проблема
Текущая авторизация через SMS в Pyrogram часто не работает (Telegram не присылает код, если нет активной сессии на другом устройстве). Вход по QR-коду — единственный надежный способ авторизовать бота.

## 2. Архитектурный подход к решению
*   Использовать метод `ExportLoginToken` из `pyrogram` для создания сессии.
*   **Тройное дублирование QR**: Чтобы консоль не "съела" QR из-за кривого шрифта, мы будем выводить его 3 способами:
    1. Изображением `login_qr.png` в папке скрипта (как самый надежный бэкап).
    2. Готовой ссылкой `tg://login?token=...` в консоли (клик по ней откроет Desktop).
    3. QR-кодом в терминале (псевдографикой).
*   **Изоляция зависимостей**: Зависимость для генерации картинок (`qrcode[pil]`) НЕ должна попасть в основной `requirements.txt` бота, так как скрипт авторизации запускается один раз администратором.

---

## 3. Задачи для разработчика (Tasks)

Ниже представлено разбиение на задачи. Выполняйте их последовательно.

### Задача 1: Разработка core-логики и тестов
Сначала мы реализуем логику генерации ссылок и картинок, и сразу покроем её Black-Box тестами (без подключения к живому API Telegram).

*   **Что сделать:**
    1. Создать файл `src/qr_utils.py`.
    2. Написать функцию `generate_qr_link(token: bytes) -> str`, которая принимает токен (байты) и возвращает строку `tg://login?token=...` (не забудьте `base64.urlsafe_b64encode`).
    3. Написать функцию `generate_qr_image(link: str, filename: str = "login_qr.png") -> None`, которая принимает ссылку и сохраняет PNG картинку с помощью библиотеки `qrcode`.
    4. Создать файл `tests/test_qr_utils.py` и написать тесты с использованием `pytest` и фиктивного токена `b"fake_token_data"`, проверяющие обе функции.
*   **Как проверить (для разработчика и ревьюера):**
    *   Запустите `pytest tests/test_qr_utils.py`. Тесты должны гореть зеленым.
    *   В папке с тестами должен появиться файл `login_qr.png` с валидным QR-кодом, который читается сканером смартфона (там должен быть текст `tg://login?token=...`).

### Задача 2: Написание скрипта `login_qr.py`
Напишем сам скрипт, который будет общаться с Telegram API.

*   **Что сделать:**
    1. В корне проекта создать файл `login_qr.py` (можно взять за основу существующий `login_userbot.py`).
    2. Добавить обработчик отсутствия библиотеки: в начале файла `try: import qrcode except ImportError: print("Выполните pip install 'qrcode[pil]'")` и завершить работу.
    3. Использовать `Client(..., in_memory=True)` для временной сессии.
    4. Использовать метод `app.invoke(functions.auth.ExportLoginToken(...))` для получения токена.
    5. Вызвать функции из Задачи 1 для вывода ссылки и сохранения картинки, а также вывести QR в консоль (используя встроенный метод `qrcode`).
    6. Написать бесконечный асинхронный цикл `while True:`, который спит пару секунд, затем через `ExportLoginToken` проверяет статус. Если сервер вернул `types.auth.LoginTokenSuccess`, выходим из цикла.
    7. В конце скрипта вызвать `app.export_session_string()` и крупно, красиво вывести полученную строку в консоль, прося пользователя вставить её в `.env`.
*   **Как проверить (для разработчика и ревьюера):**
    *   Установите `pip install "qrcode[pil]"`.
    *   Запустите `python login_qr.py`.
    *   Скрипт должен вывести QR в консоль, ссылку, и создать PNG файл.
    *   Отсканируйте код приложением Telegram.
    *   Скрипт должен сам понять, что вы авторизовались, и выдать длинную строку (session string) в консоль. **Не коммитьте эту строку!**

### Задача 3: Интеграция и документация
Финальный шаг — обновление документации и избавление от старого кода.

*   **Что сделать:**
    1. Обновить `README.md` и `RUNBOOK.md`. Убрать упоминания `login_userbot.py` и старого способа (или перенести их в раздел TroubleShooting), добавив инструкцию о запуске `login_qr.py`.
    2. Добавить требование выполнить `pip install "qrcode[pil]"` перед генерацией сессии.
    3. Убедиться, что `requirements.txt` проекта **НЕ ИЗМЕНИЛСЯ**.
*   **Как проверить (для разработчика и ревьюера):**
    *   Откройте `README.md` и прочитайте процесс установки проекта с нуля глазами новичка. Если шаги понятны — задача выполнена.
    *   Проверьте git diff для `requirements.txt` — он должен быть пустым.
