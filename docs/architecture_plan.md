# План архитектурного рефакторинга (Том 5 Quick Wins — для Джуниор-разработчиков)

Этот документ описывает детальный план внедрения топ-5 архитектурных улучшений для проекта `tg2book`. Цель — сделать кодовую базу более предсказуемой, стабильной и читаемой.

**Данный план специально адаптирован для джуниор-разработчиков.** Каждая задача разбита на понятные шаги с критериями приёмки и, где применимо, указаниями по написанию black-box тестов.

---

## Приоритет выполнения

Рекомендуется следующий порядок внедрения:

1.  **Типизация (Type Hinting & Mypy)**
2.  **Линтинг и форматирование (Ruff)**
3.  **Декомпозиция (Разделение логики)** 
4.  **Единый слой конфигурации (pydantic-settings)**
5.  **Базовый CI Pipeline**

---

## 1. Внедрение строгой статической типизации (Type Hinting + `mypy`)

**Цель:** Описать все входные и выходные параметры функций, чтобы IDE "понимали" структуры данных без необходимости угадывать.

**Критерии приёмки:** Код проходит проверку `mypy` без ошибок. Все методы в `bot.py`, `dropbox_module.py` и `epub_functions.py` аннотированы типами.

**Шаги реализации:**
- [ ] **Шаг 1.1:** Добавить `mypy` в зависимости для тестирования (`requirements-test.txt`).
- [ ] **Шаг 1.2:** В `bot.py` импортировать нужные типы: `from typing import Optional, List, Dict`.
- [ ] **Шаг 1.3:** Добавить `mypy` в `Makefile`. Создай команду `typecheck: docker compose exec tg2book mypy bot.py dropbox_module.py epub_functions.py`.
- [ ] **Шаг 1.4:** Добавить типы для обработчиков `TelegramToEpub` (методы `start`, `help`, `handle_message`).
  - *Подсказка:* Аргументы: `update: Update, context: ContextTypes.DEFAULT_TYPE`.
- [ ] **Шаг 1.5:** Добавить типы для вспомогательных методов:
  - `strip_emojis(self, text: str) -> str`
  - `extract_title(self, text: str) -> str`
  - `get_message_text(self, message: Message) -> str`
  - `get_first_link(self, message: Message) -> str`
  - `get_source_info(self, message: Message) -> str`
- [ ] **Шаг 1.6:** Проверить и типизировать `dropbox_module.py` и `epub_functions.py` (убедиться, что возвращаемые значения и аргументы функций явно указаны).
- [ ] **Шаг 1.7:** Запустить `make typecheck` локально и исправить все выведенные ошибки.

**Тестирование:**
- [ ] Написать юнит-тест (если его нет), который проверяет, что `strip_emojis` принимает строку и возвращает строку. Запустить `make test`.

## 2. Подключение сверхбыстрого линтера и форматтера (`Ruff`)

**Цель:** Автоматизировать форматирование кода и проверку на простые синтаксические и стилистические ошибки.

**Критерии приёмки:** Настроен конфигурационный файл `pyproject.toml` для Ruff. Команды для линтинга и форматирования добавлены в `Makefile`. Локальный запуск проходит без ошибок.

**Шаги реализации:**
- [ ] **Шаг 2.1:** Добавить `ruff` в `requirements-test.txt`.
- [ ] **Шаг 2.2:** Создать файл `pyproject.toml` в корне проекта (если нет) и добавить базовые настройки Ruff:
  ```toml
  [tool.ruff]
  line-length = 100
  ```
- [ ] **Шаг 2.3:** Добавить новые команды в `Makefile`:
  - `format:` `docker compose exec tg2book ruff check --fix . && ruff format .`
  - `lint:` `docker compose exec tg2book ruff check .`
- [ ] **Шаг 2.4:** Запустить `make format` и закоммитить автоформатированные изменения.
- [ ] **Шаг 2.5:** Запустить `make lint` и исправить оставшиеся ошибки вручную (ручные правки, которые Ruff не смог исправить авто-фиксом).

**Тестирование:**
- [ ] *Блэкбокс-тест не требуется напрямую для линтера, проверкой служит успешный выходной код (exit code 0) команды `make lint`.*

## 3. Декомпозиция монолитного `bot.py`

**Цель:** Разгрузить файл `bot.py`. В нём должен остаться только функционал, напрямую связанный с инициализацией Telegram-бота и обработкой (handlers) входящих сообщений.

**Критерии приёмки:** Чистые функции вынесены в `utils/text_utils.py`. Логика сборки EPUB и отправки в Dropbox вынесена в `services/epub_service.py`. Тесты продолжают проходить.

**Шаги реализации:**
- [ ] **Шаг 3.1:** Создать директорию `utils` и файл `utils/text_utils.py`.
- [ ] **Шаг 3.2:** Перенести следующие методы из класса `TelegramToEpub` (сделав их обычными функциями) в `text_utils.py`:
  - `strip_emojis`
  - `extract_title`
  - `sanitize_filename`
  - `format_message`
- [ ] **Шаг 3.3:** Импортировать перенесённые функции обратно в `bot.py` и заменить их вызовы (например, `self.strip_emojis()` на `strip_emojis()`).
- [ ] **Шаг 3.4:** Запустить тесты `make test`, чтобы убедиться, что базовый функционал текста не сломался.
- [ ] **Шаг 3.5:** Создать директорию `services` и файл `services/epub_service.py`.
- [ ] **Шаг 3.6:** Перенести логику связки "генерация EPUB -> загрузка в Dropbox" в `epub_service.py` (создав, например, асинхронную функцию `process_and_upload_epub`).
- [ ] **Шаг 3.7:** Интегрировать `epub_service.py` в `bot.py:handle_message`.
- [ ] **Шаг 3.8:** Запустить все тесты (`make test`) и убедиться, что они проходят.

**Тестирование (Black-box):**
- [ ] Написать (или обновить существующий) тест верхнего уровня (end-to-end мок) в `test_bot.py`, который эмулирует получение текстового сообщения и проверяет вызов сервиса `process_and_upload_epub` со всеми правильными параметрами.

## 4. Вынос конфигурации в единый слой

**Цель:** Убрать прямые вызовы `os.getenv` из кода приложения и собрать конфигурацию в один типизированный класс через `pydantic-settings`.

**Критерии приёмки:** В проекте нет вызовов `os.getenv` для настройки приложения. Все настройки грузятся через объект `settings` из файла `config.py`.

**Шаги реализации:**
- [ ] **Шаг 4.1:** Добавить `pydantic-settings` в `requirements.txt`.
- [ ] **Шаг 4.2:** Создать файл `config.py` в корне проекта.
- [ ] **Шаг 4.3:** Написать класс конфигурации в `config.py`:
  ```python
  from pydantic_settings import BaseSettings, SettingsConfigDict

  class Settings(BaseSettings):
      TELEGRAM_BOT_TOKEN: str
      DROPBOX_REFRESH_TOKEN: str
      DROPBOX_APP_KEY: str
      DROPBOX_APP_SECRET: str

      model_config = SettingsConfigDict(env_file='.env', env_file_encoding='utf-8')

  settings = Settings()
  ```
- [ ] **Шаг 4.4:** В `.env` или моках тестов убедиться в наличии переменных.
- [ ] **Шаг 4.5:** Заменить `os.getenv('TELEGRAM_BOT_TOKEN')` в `bot.py` на `settings.TELEGRAM_BOT_TOKEN`.
- [ ] **Шаг 4.6:** Сделать то же самое в `dropbox_module.py` для `DROPBOX_*` ключей.
- [ ] **Шаг 4.7:** Обновить файлы тестов. Вместо патчинга словаря `os.environ`, теперь нужно делать патчинг импортированного объекта `settings` (через `unittest.mock.patch`).
- [ ] **Шаг 4.8:** Запустить тесты.

**Тестирование:**
- [ ] Написать тест на структуру самого `config.py`, который искусственно устанавливает `os.environ` с тестовыми данными, инициализирует класс `Settings` и проверяет, что поля заполнились корректно.

## 5. Настройка базового CI (Continuous Integration) конвейера

**Цель:** Настроить автоматизацию проверок на сервере, чтобы разработчики не ломали основную ветку сломанными тестами или плохим стилем кода.

**Критерии приёмки:** При пуше (push) в основную ветку GitHub Actions (или GitLab CI) запускает: форматтер, типизацию и юнит-тесты. Пайплайн завершается зелёной галочкой (success).

**Шаги реализации:**
- [ ] **Шаг 5.1:** Создать структуру папок: `.github/workflows/` (в корне).
- [ ] **Шаг 5.2:** Создать там файл `ci.yml`.
- [ ] **Шаг 5.3:** Написать шаги для GitHub Actions (пример):
  - Checkout кода (`actions/checkout@v3`).
  - Установка Python (например, 3.12, как мы видим по логам тестов: `actions/setup-python@v4`).
  - Установка зависимостей (`pip install -r requirements.txt -r requirements-test.txt`).
  - Запуск `ruff check .`
  - Запуск `mypy bot.py dropbox_module.py epub_functions.py`
  - Запуск `pytest`
- [ ] **Шаг 5.4:** Закоммитить и запушить изменения.
- [ ] **Шаг 5.5:** Перейти во вкладку "Actions" в GitHub и убедиться, что пайплайн прошёл успешно. Ошибки в пайплайне исправить.

**Тестирование:**
- [ ] Само выполнение пайплайна в репозитории является тестом этого шага. Убедиться, что намеренно сломанный тест "валит" CI.
