
| № | Практика (Harness Engineering) | Описание и почему это дает максимальный эффект | Инструменты / Артефакты |
| :--- | :--- | :--- | :--- |
| **2** | **Линтеры с инструкциями по исправлению** (Remediation Instructions) | **Эффект: Максимальный.** Если CI просто падает с ошибкой, агент работает вслепую. Если линтер вместе с ошибкой выдает текстовое указание (например, «Используйте DTO вместо прямого импорта UI»), агент мгновенно применяет нужный паттерн. | Кастомные правила линтеров (ESLint для TS, Ruff для Python), структурные тесты. |
| **3** | **Читаемая диагностика для агентов** (Agent Legibility) | **Эффект: Очень высокий.** Агенту недостаточно логов сборки. Чтобы он мог автономно чинить баги без QA-инженеров, ему нужен доступ к снимкам DOM (через протокол Chrome DevTools) и прямым запросам к метрикам и логам. | Интеграция Chrome DevTools, LogQL/PromQL, машиночитаемые логи ошибок сборки. |
| **4** | **Синтетическое ревью кода** (Agent-to-Agent Review) | **Эффект: Высокий.** Главное «узкое горлышко» — ожидание ревью от человека. Настройка узкоспециализированного агента-ревьюера, который проверяет код автора и заставляет его вносить правки в цикле («Ralph Wiggum loop»), радикально повышает пропускную способность. | Бот-ревьюер (на базе мощной модели, например, o1/o3) для PR, автоматические комментарии к коду. |
